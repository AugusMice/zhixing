# 用 AI 批量出题

AI 适合做「草稿生成 + 格式整理」，不适合直接信答案。推荐流程：

1. 先让 AI 设计知识点树，人工删改。
2. 再按知识点分批生成题目 JSON。
3. 人工核对答案、解析、评分细则。
4. 放进 `content/questions/`，打开应用控制台确认没有校验错误。

> 高考真题请优先从正规渠道获取并人工录入。AI 凭空「回忆」真题，年份、题号、选项都可能编造。

---

## 提示词 1：设计知识点树

把下面这段整体发给模型，替换「科目」和「考试范围」。

```text
你是一位熟悉中国高考的学科教研员。请为「数学」设计一份知识点树，用于间隔重复学习系统。

要求：
1. 按教材/考纲拆成 6~10 个板块（group），覆盖考试主干；每个板块下再拆 4~10 个可独立练习的知识点。
2. 每个知识点是一个可独立练习、可判断掌握程度的小单元。
3. 前置关系只保留真正必要的：不会 A 就很难做 B；不要成环。
4. 相关关系只连真正有迁移价值的点，不要把所有关系都塞进 related。
5. 标出高考考频、重要程度、学习难度（1~5）。
6. 用 JSON 数组输出，不要任何解释文字或 Markdown 代码围栏。

字段：
- id: 小写英文 + 连字符，以科目缩写开头，如 math-func
- subjectId: "math"
- name: 中文名，不超过 12 字
- group: 板块名，如「函数与导数」
- description: 2~4 句理论速览，说明核心概念、常用方法、易错点
- parents: 前置知识点 id 数组，没有就写 []
- related: 相关知识点 id 数组，没有就写 []
- examFrequency: 1~5 的整数，5 表示几乎年年考
- importance: 1~5 的整数
- difficulty: 1~5 的整数

输出示例：
[
  {
    "id": "math-func",
    "subjectId": "math",
    "name": "函数基础",
    "group": "函数与导数",
    "description": "函数的概念、定义域、值域与表示方法。判断两个函数是否相同，要看定义域和对应关系是否都相同。",
    "parents": [],
    "related": ["math-domain"],
    "examFrequency": 5,
    "importance": 5,
    "difficulty": 2
  }
]
```

拿到结果后：

- 检查板块是否 6~10 个、知识点是否覆盖主干。
- 检查前置边是否必要；太多会让每日计划锁死。
- 检查考频/重难是否全是 3（模型偷懒时常见）；需要人工校准。
- 把 id 固定下来，后面出题要引用。

## 提示词 2：按知识点出题

一次不要超过 10 道，否则模型容易偷懒、重复、编号错乱。把知识点列表和已用 id 一起给它。

```text
你是一位中国高考「数学」命题人。请为下面 3 个知识点各出 2 道题，共 6 道。

知识点：
- math-domain 函数定义域：分母不为零、偶次根号内非负、对数真数为正。
- math-derivative 导数与单调性：利用导数符号判断单调区间。
- math-prob 古典概型：有限等可能样本空间下的概率计算。

要求：
1. 题型混合：单选、填空、判断、大题都要有；本批至少 1 道大题。
2. 难度 1~5 分布：1~2 各 1 道，3 至少 2 道，4~5 至少 1 道。
3. 风格贴近高考：题干简洁，选项有干扰性，不考偏难怪。
4. 每道题必须关联 1~2 个上面的知识点，kpIds 只能用给定 id。
5. 每题都要写 explanation，解释「为什么」以及常见错误。
6. 大题必须给 rubric（可勾选的采分点，3~6 项，每项 1~3 分）和 reference。
7. 题干、选项、解析中的公式用 LaTeX：行内 $...$；JSON 中反斜杠写两次。
8. 填空的 accept 要覆盖常见等价写法（全角/半角、大小写、带不带单位）。
9. 单选 answer 必须是选项 key；多选 answer 是 key 数组；判断 answer 是布尔值。
10. 只输出 JSON 数组，不要 Markdown 代码围栏，不要前后解释。

题目字段：
id（唯一，如 math-101）、subjectId、kpIds、type（single/multiple/judge/fill/short）、
difficulty、stem、options（选择题）、answer、blanks（填空）、rubric/reference（大题）、
explanation、source（写 "AI 草稿"）、tags（可选）。

输出示例（单选）：
{
  "id": "math-101",
  "subjectId": "math",
  "kpIds": ["math-domain"],
  "type": "single",
  "difficulty": 1,
  "stem": "函数 $f(x)=\\sqrt{2-x}$ 的定义域是（　）",
  "options": [
    { "key": "A", "text": "$(-\\infty,2]$" },
    { "key": "B", "text": "$(-\\infty,2)$" },
    { "key": "C", "text": "$[2,+\\infty)$" },
    { "key": "D", "text": "$(2,+\\infty)$" }
  ],
  "answer": "A",
  "explanation": "偶次根号内必须非负，所以 $2-x\\ge 0$，即 $x\\le 2$。",
  "source": "AI 草稿"
}
```

## 提示词 3：自检（强烈建议）

生成后，把结果原样发回去，让模型做一次「只挑错、不改写」的审查：

```text
下面是一批准备入库的高考数学题 JSON。请逐题检查：
1. 答案是否正确；单选是否只有一个正确项；多选是否漏选/多选。
2. 题干条件是否充分、是否有歧义、是否超纲。
3. explanation 是否与答案一致。
4. 大题 rubric 是否能覆盖主要得分步骤，总分是否合理。
5. JSON 字段是否符合约定，kpIds 是否都在给定列表里。

只输出问题清单：题号、问题、建议。不要重写整批题，不要输出客套话。

题目 JSON：
<粘贴>
```

## 入库前人工检查清单

- [ ] 答案自己算过一遍，不只信 AI。
- [ ] 选择题干扰项确实有迷惑性，不是凑数。
- [ ] 填空题的 `accept` 覆盖了你会写的写法。
- [ ] 大题评分细则能逐条勾选，不是「过程完整」。
- [ ] 每题 `kpIds` 不超过 3 个，且归属正确。
- [ ] `id` 没和已有题目重复。
- [ ] 打开应用控制台，没有 `[知星] 题库内容有问题`。

---

## 小技巧

- 让模型**先列 10 个考点再出题**，重复率会明显下降。
- 一次只给 1~3 个知识点，比「给我 50 道数学题」质量高得多。
- 对大题，先让它写评分细则，再让它按细则写参考解答，两者更容易对齐。
- 如果模型反复算错，换一种问法让它「分步计算并逐步检查」，而不是直接要答案。
- 生成结果先存成 `content/questions/_draft.json`，人工筛完再改名；应用会自动加载所有 JSON，草稿也会进题库，所以**不要长期把半成品放在这个目录**。
